# WorkOrders

เว็บแอปสำหรับทีมช่างซ่อม — สร้าง work order, มอบหมายงาน, วางแผนวัน/เวลา และติดตามสถานะ
ออกแบบให้ใช้ได้ทั้งบนมือถือและเดสก์ท็อป (UI เป็นภาษาอังกฤษ)

ไม่ต้องมี Node.js ไม่ต้อง build — เป็นไฟล์ HTML/CSS/JS ธรรมดา ที่คุยกับ Supabase โดยตรง

---

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าเว็บ |
| `styles.css` | สไตล์ทั้งหมด (รองรับ light/dark อัตโนมัติตามเครื่อง) |
| `config.js` | **ไฟล์เดียวที่คุณต้องแก้** — ใส่ Supabase URL/key, ชื่อแอป, หมวดหมู่งาน, ช่วงเวลานัด |
| `db.js` | ชั้นข้อมูล มี 2 โหมด: Supabase จริง กับ demo (localStorage) |
| `app.js` | ตรรกะ UI ทั้งหมด |
| `schema.sql` | สคริปต์สร้างตาราง + RLS + realtime บน Supabase |
| `manifest.webmanifest` | ทำให้ "Add to Home Screen" บนมือถือดูเหมือนแอป |

## ลองเล่นก่อน (demo mode)

ยังไม่ต้องตั้งค่าอะไรเลย เปิดดูได้ทันที

```bash
python3 -m http.server 8777
```

แล้วเปิด http://127.0.0.1:8777 → ล็อกอินด้วยอีเมลอะไรก็ได้ + รหัส `123456`

โหมดนี้เก็บข้อมูลไว้ใน localStorage ของเบราว์เซอร์เครื่องนั้นเท่านั้น **ยังไม่แชร์กับใคร**
มีข้อมูลตัวอย่าง (ลูกค้า 3 ราย, งาน 5 ใบ, ทีม 4 คน) ให้ลองกดเล่น
ล้างข้อมูลตัวอย่างได้จากเมนูรูปโปรไฟล์มุมขวาบน → *Reset demo data*

## ตั้งค่าใช้งานจริง

### 1. สร้าง Supabase project

1. ไปที่ https://supabase.com → *New project* (แผน Free พอสำหรับ 8 คนสบายๆ)
2. ตั้งรหัสผ่าน database แล้วรอสัก 2 นาทีให้ project พร้อม

### 2. สร้างตาราง

1. ใน Supabase Studio → **SQL Editor** → *New query*
2. คัดลอกเนื้อหาทั้งหมดใน `schema.sql` มาวาง → กด **Run**
3. ควรขึ้น *Success* — ตาราง `profiles`, `customers`, `work_orders`,
   `work_order_assignees`, `work_order_notes` จะถูกสร้างพร้อม RLS และ realtime

สคริปต์นี้รันซ้ำได้ ไม่พังของเดิม

### 3. เปิดอีเมล OTP (รหัส 6 หลัก)

ค่าเริ่มต้นของ Supabase ส่งเป็น magic link อย่างเดียว แอปนี้ใช้ **รหัส 6 หลัก**
เพราะใช้ได้ทุกที่ (รวมถึงตอนเปิดจากมือถือคนละเครื่องกับที่เปิดอีเมล)

1. **Authentication → Emails →** เลือกเทมเพลต **Magic Link**
2. เพิ่มบรรทัดนี้เข้าไปในเนื้ออีเมล:

   ```html
   <p>Your sign-in code: <strong>{{ .Token }}</strong></p>
   ```

   (เก็บ `{{ .ConfirmationURL }}` เดิมไว้ก็ได้ — กดลิงก์ก็ยังเข้าได้เหมือนกัน)
3. **Authentication → URL Configuration →** ใส่ URL ที่จะ deploy ลงใน *Site URL*
   และ *Redirect URLs*

> ⚠️ อีเมลของ Supabase แผนฟรีจำกัดที่ ~3-4 ฉบับต่อชั่วโมง
> ทีม 8 คนที่ล็อกอินครั้งเดียวแล้วค้าง session ไว้จะไม่มีปัญหา
> แต่ถ้าจะให้ทนกว่านี้ ให้ต่อ SMTP ของตัวเองที่ **Project Settings → Authentication → SMTP Settings**
> (Resend / SendGrid / Gmail SMTP ใช้ได้หมด)

### 4. ใส่ key ลง `config.js`

ไปที่ **Project Settings → Data API** แล้วคัดลอกมา 2 ค่า

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi...",
  ...
};
```

`anon key` ปลอดภัยที่จะอยู่ในหน้าเว็บ — ตัวที่กันข้อมูลจริงๆ คือ RLS policy ใน `schema.sql`
ซึ่งบังคับว่าต้องล็อกอินก่อนถึงจะอ่าน/เขียนได้ **อย่าเอา `service_role` key มาใส่เด็ดขาด**

### 5. Deploy

เป็นไฟล์ static ล้วน จะโฮสต์ที่ไหนก็ได้:

- **Netlify Drop** — ลากโฟลเดอร์ทั้งอันไปวางที่ https://app.netlify.com/drop เสร็จใน 10 วินาที
- **Vercel** — `vercel deploy` หรือเชื่อมกับ GitHub repo
- **Cloudflare Pages / GitHub Pages** — ชี้ไปที่โฟลเดอร์นี้ได้ตรงๆ

เสร็จแล้วส่งลิงก์ให้ทีม 8 คน แต่ละคนล็อกอินด้วยอีเมลตัวเอง
ระบบจะสร้าง profile ให้อัตโนมัติ และโผล่ในหน้า **Team** ทันที

### 6. ตั้งตัวเองเป็น admin (ทางเลือก)

หลังล็อกอินครั้งแรก รันใน SQL Editor:

```sql
update public.profiles set role = 'admin' where email = 'boonchuay.k@northeastern.edu';
```

ตอนนี้ `admin` ต่างจาก `member` แค่สิทธิ์แก้ profile คนอื่นเท่านั้น
ทุกคนยังสร้าง/แก้/ปิดงานได้หมด (เหมาะกับทีมเล็กที่ไว้ใจกัน)
ถ้าอยากล็อกให้แน่นกว่านี้ แก้ policy ในส่วน Row Level Security ของ `schema.sql`

## ใช้งานบนมือถือ

เปิดลิงก์ใน Safari (iOS) หรือ Chrome (Android) → **Share → Add to Home Screen**
จะได้ไอคอนบนหน้าจอ เปิดแบบเต็มจอไม่มีแถบเบราว์เซอร์ เหมือนแอปจริง

Layout เปลี่ยนตามขนาดจอเอง:
- **มือถือ** — แถบแท็บด้านล่าง, ปุ่ม + ลอย, การ์ดเรียงแนวตั้ง, bottom sheet, ปุ่มสูง 44px กดง่าย
- **เดสก์ท็อป** — sidebar ซ้าย, การ์ดเรียงเป็น grid, ปฏิทินแบบ 7 คอลัมน์, modal กลางจอ

## ฟีเจอร์ตามที่ขอไว้

| ที่ขอ | ทำงานยังไง |
|---|---|
| **1. ล็อกอินผูกอีเมล** | Supabase Auth ส่งรหัส 6 หลักไปที่อีเมล ไม่ต้องจำรหัสผ่าน |
| **2. สร้าง work order** | ปุ่ม + → ใส่หัวข้อ, หมวดหมู่, ความเร่งด่วน, รายละเอียด |
| **3. อัปเดตสถานะ** | 6 สถานะ: Open / Scheduled / In progress / On hold / Completed / Cancelled กดเปลี่ยนได้จากหน้ารายละเอียด และระบบบันทึกลง log ให้อัตโนมัติ |
| **4. ข้อมูลลูกค้าไม่ต้องพิมพ์ซ้ำ** | ตาราง `customers` เก็บ ชื่อ/เบอร์/อีเมล/เลขห้อง/ตึก/ที่อยู่/โน้ต ครั้งต่อไปพิมพ์ค้นหาแล้วเลือก ระบบเติมที่อยู่ให้เอง (แก้ทับได้ถ้างานนี้อยู่คนละที่) |
| **5. มอบหมายคนทำงาน** | กดชื่อคนในทีมเพื่อ assign ได้หลายคนต่องาน กดซ้ำเพื่อเอาออก |
| **6. วางแผนวัน/เวลา** | ปุ่มลัด Today / Tomorrow / วันถัดไป + ช่วงเวลาสำเร็จรูป + เลือกระยะเวลางาน หน้า **Schedule** ดูเป็นสัปดาห์ พร้อมกล่อง "Waiting to be planned" ที่ **ลากมาวางในวันที่ต้องการได้** (เดสก์ท็อป) หรือแตะเพื่อเลือกวัน (มือถือ) |

เพิ่มเติมที่ให้มาด้วย:
- ทุกคนเห็นการเปลี่ยนแปลง **real-time** (Supabase Realtime) ไม่ต้องรีเฟรช
- ค้นหาจากหัวข้อ / ชื่อลูกค้า / เบอร์โทร / เลขห้อง / เลขที่งาน
- ตัวกรอง "Assigned to me" สำหรับช่างที่อยากดูเฉพาะงานตัวเอง
- โน้ต/คอมเมนต์ในแต่ละงาน พร้อม log การเปลี่ยนสถานะ
- แตะเบอร์โทรเพื่อโทรออก, ปุ่มเปิด Google Maps จากที่อยู่
- งานที่เลยเวลานัดแล้วยังไม่ปิด จะขึ้นเวลาเป็นสีแดง
- ประวัติงานทั้งหมดของลูกค้าแต่ละราย

## ข้อจำกัดที่ควรรู้

- **ยังไม่มีการอัปโหลดรูป** — ถ้าอยากแนบรูปหน้างาน ต้องเพิ่ม Supabase Storage
- **ยังไม่มี push notification** — ทุกคนต้องเปิดแอปดูเอง (จะเพิ่มอีเมลแจ้งเตือนผ่าน Supabase Edge Function ได้)
- **ยังไม่มีรายงาน/สถิติ** — มีแค่ตัวนับจำนวนงาน ยังไม่มีกราฟหรือ export CSV
- ตอนนี้ทุกคนที่ล็อกอินได้ **เห็นและแก้ได้ทุกงาน** ตั้งใจให้เป็นแบบนี้สำหรับทีมเล็ก
  ถ้าต้องการจำกัดให้ช่างเห็นเฉพาะงานตัวเอง ต้องแก้ RLS policy `work_orders_all` ใน `schema.sql`
